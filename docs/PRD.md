# HZone 产品需求文档（PRD）

版本：v1.0 ｜ 日期：2026-10-19 ｜ 状态：已评审（设计树共识）

> 术语以根目录 [GLOSSARY.md](../GLOSSARY.md) 为准。本文档使用其中定义的：说说、日志、@、可见名单、不打扰、双向好友、邀请码、评论、站内信、内容。

---

## 1. 背景与动机

QQ 空间的替代品，只保留两个内容形态：**日志（blog）** 和 **说说**。做这个产品的动机：

1. **广告太多**：QQ 空间充斥广告与推荐流，无法安静地写和看。
2. **数据不自主**：内容锁在腾讯云端，外部 agent（如 Claude）无法通过 MCP 访问，个人的内容无法被自己的工具读取和整理。
3. **社交过载**：点赞、推送、Feed 流把"分享"变成了"表演"。HZone 回到最原始的形态——我写，我指定谁看。

## 2. 产品定位

**私密的定向分享社区**：用户发布日志与说说，通过 @ 指定谁能看到每条内容；没有推送通知、没有聚合动态流。

- 目标用户：亲友小圈子（十几人以内），自托管部署。
- 一句话原则：**内容永远只流向作者指定的人，且绝不主动打扰任何人。**

## 3. 核心原则：不打扰

这是产品的第一性原则，所有功能设计不得违背：

| 维度 | 规则 |
|---|---|
| 推送 | **零站外推送**：无邮件通知、无移动端推送（APNs/FCM） |
| 聚合 | **无 Feed / 动态流**：不存在"好友动态"页面 |
| 通知 | 所有事件（被 @、收到评论）只产生**登录时可见的站内信** |
| 发现 | 内容发现只有两条路：被 @ 后在自己的列表里看到；主动访问作者主页 |

## 4. 用户与角色

| 角色 | 说明 |
|---|---|
| 游客 | 未登录者。除登录/注册页外无任何可见内容 |
| 用户 | 注册并登录的成员。可发布、@、评论、管理自己的内容 |
| 管理员 | 第一个账号（初始化向导创建）。额外拥有：邀请码全局开关、媒体上限配置、SMTP 配置、用户管理 |

- **账号标识**：邮箱即账号（登录名=邮箱），昵称仅用于显示和 @，不设独立用户名。
- **双向好友**：互相确认的熟人关系。好友关系不授予内容可见权，只决定 @ 的候选范围。

## 5. 领域模型核心规则

### 5.1 @ 与可见名单

- **@ 名单 = 可见名单**。一条内容的可见者有且仅有：作者 + 被 @ 的人。没有公开/好友/私密开关，只有这一条规则。
- 不 @ 任何人 = 私密内容，仅作者可见。
- 只能 @ **双向好友**。
- 可见名单**仅作者可修改**（发布后可增删）；被 @ 者不能把内容扩散给自己的好友。
- **移除立即失权**：从名单中移除的人即刻失去查看权，权限跟着名单走，没有"永久票据"，其"已读"状态一并清除。
- **新增名单成员**：与首次 @ 一致，产生登录时可见的站内信。
- @ 对象作为**独立字段**存储（不混入正文语法），可多选；日志与说说一致。

### 5.2 内容

| | 说说 | 日志 |
|---|---|---|
| 正文 | 文本，字数不限 | Markdown，无长度限制 |
| 标题 | 无 | 必须有 |
| 媒体 | 图片 ≤ 9 张；或视频；或音频 | 图片（插入正文引用） |
| @ 字段 | 有 | 有 |

- **编辑**：作者可随时编辑正文与媒体（可见名单修改见 5.1）。
- **删除**：硬删除，级联清理评论、相关站内信和媒体文件；无回收站。数据安全靠数据库与媒体目录备份解决。

### 5.3 评论

- 可见名单内成员可对内容发表评论，评论对**整个可见名单**可见。
- 评论产生站内信（给作者；给被回复者，若未来支持楼中楼）。

### 5.4 站内信

- 平台唯一的通知形态。触发事件：被 @（含事后被加入名单）、收到评论。
- 登录后可见（红点/角标），用户打开站内信列表查看；对应内容从站内信可直达。
- 站内信本身支持标记已读；内容被删除时相关站内信级联删除。

## 6. 功能需求

### 6.1 初始化向导（首次启动）

实例首次访问时进入向导：创建管理员账号 → 配置 SMTP（发验证/重置邮件必需）→ 进入主界面。向导完成后不再出现。

### 6.2 注册与登录

- **注册流程**：持有邀请码 → 填写邀请码 + 邮箱 + 密码 → 系统发送验证邮件 → 点击链接（或填验证码）→ 账号生效。
- **邀请码规则**：
  - 所有用户均可生成自己的邀请码；
  - 每个码**一次性**、带**有效期**（默认 7 天）；
  - 每人同时最多 3 个有效码（配额）；
  - 管理员可全局关闭邀请功能（兜底开关）。
- **登录**：邮箱 + 密码。密码 bcrypt 存储，长度下限校验。
- **忘记密码**：邮件重置链接，不做独立找回通道。

### 6.3 内容发布

- 发布说说：文本 + 附件（≤9 图 / 1 视频 / 1 音频）+ 选择 @ 对象（双向好友多选）。
- 发布日志：标题 + Markdown 编辑器 + 图片插入 + 选择 @ 对象。
- 均可在发布前预览可见名单。

### 6.4 浏览

- **我的内容**：时间线（按发布时间倒序），支持筛选类型（说说/日志）。
- **收到的内容**：我被 @ 的所有内容列表（核心页面之一）。
- **好友主页**：主动访问某位好友，看到的是"我可见的Ta的内容"（即 Ta 发的、@ 了我的内容）。
- 无任何 Feed、推荐、热门模块。

### 6.5 评论

内容详情页内，可见名单成员可发表评论；评论按时间排列，不做点赞。

### 6.6 搜索

- 第一版为**基础关键词搜索**：搜自己的日志标题/正文（说说正文一并支持）。
- 实现：SQL `LIKE` 起步；搜索接口做抽象，未来可平滑替换为各数据库的全文索引（SQLite FTS5 / SQLServer / PG / MySQL 全文方案行为不一，第一版不引入）。

### 6.7 导入与导出（内容迁移与备份通道）

- **导出**：整站打包导出 zip —— 所有日志为 .md 文件 + 说说文本与媒体文件 + 元数据清单。**导出即备份**。
- **导入**：支持 zip 批量导入 md 日志（方便从 QQ 空间等平台迁移）：
  - 导入内容默认**私密**（@ 无人，仅自己可见）；
  - 导入后支持**批量编辑 @ 名单**（多选内容 → 批量追加 @ 对象）。

### 6.8 开放 API（Agent 接入地基）

- 第一版交付 **PAT（个人访问令牌）+ REST API**：
  - 用户在设置页生成/吊销令牌；令牌 = 本人身份；
  - 能力覆盖：发说说/发日志、读自己的内容、读可见名单内的内容、评论、搜索；
  - **可见性规则与界面完全一致**：API 永远只返回调用者可见名单内的内容。
- MCP server **不在第一版范围**，但 API 是其地基：后续在 REST API 之上包一层 MCP 即可让 Claude 等 agent 直接读写。

### 6.9 主题与本地化

- **主题**：产品有统一的骨架风格，配色由用户自定义（"每户自己装修"）：
  - 所有颜色/圆角/字号走 **design token**，不写死；
  - 用户可自定义主色/背景等配色，可选预置主题作为起点；
  - 做对比度校验与实时预览；主题**跟随账号**多端同步。
- **本地化**：中文 + 英文双语包；全部文案走 i18n 框架，不硬编码。
- **界面原则**：简单但不简陋——克制的布局、足够精致的细节，不堆功能入口。

### 6.10 管理员功能

- 邀请码全局开关；用户管理（查看/禁用）。
- SMTP 配置（注册验证、密码重置邮件）。
- 媒体上限配置（见 7.2）。

## 7. 非功能需求

### 7.1 技术栈

| 层 | 选型 |
|---|---|
| 后端 | .NET 8（ASP.NET Core Web API） |
| ORM | EF Core，支持四库：SQLite（开发默认）/ SQLServer / PostgreSQL / MySQL（部署可选，连接串切换） |
| 前端 | uni-app（Vue3）：一套代码编译 H5 + Android App + iOS App；第一版**不做**小程序和桌面端 |
| 部署 | Docker 镜像（linux/amd64 + arm64），单容器含 API + H5 静态资源；卷挂载数据库文件与媒体目录 |

### 7.2 媒体存储与限制

- 媒体文件存**服务器本地磁盘目录**（路径为配置项），数据库存元数据与相对路径。
- 上限**管理员可配置**，默认值：

  | 类型 | 默认上限 | 处理 |
  |---|---|---|
  | 图片 | 单张 10 MB | 自动压缩 + 生成缩略图 |
  | 视频 | 200 MB / 5 分钟 | 超限自动压缩（需 ffmpeg；环境无 ffmpeg 时按原上限拒绝并提示） |
  | 音频 | 50 MB | 超限自动压缩 |

### 7.3 正文存储

- 正文（日志 Markdown、说说文本）**存数据库**为唯一权威数据源。
- .md 文件是**导出产物**（见 6.7），不是存储形态。

### 7.4 安全

- 密码 bcrypt；PAT 仅生成时明文展示一次，落库存哈希。
- 所有内容接口（含 API）强制可见名单校验；游客不可见任何内容。
- 邮箱验证与密码重置链接带过期时间的签名 token。

## 8. 版本边界

**第一版做**：初始化向导、邀请码注册+邮箱验证、说说/日志发布与浏览、可见名单与 @、评论、站内信、基础搜索、zip 导入/导出、PAT REST API、自定义主题、中英双语、Docker 部署、管理员后台。

**第一版不做**（后续路线图）：
- MCP server（API 打好地基后包装）
- 移动端推送、邮件通知（违背不打扰原则，除非用户主动要求变更）
- 微信小程序、桌面端
- 楼中楼评论、点赞
- 各数据库全文索引
- 批量导入时按配置指定 @ 名单（第一版仅"导入后批量编辑"）

## 9. 工程注意事项（评审记录）

1. 视频压缩依赖 ffmpeg：镜像内打包 ffmpeg 可选（考虑 arm64 体积），无 ffmpeg 时的降级行为已定义（7.2）。
2. 四库兼容靠 EF Core 抽象；开发期始终以 SQLite 跑集成测试，部署目标库的迁移在 CI 中验证。
3. 可见名单校验必须收敛到单一查询入口（数据层），界面与 API 共用，避免两套口径。
4. 删除的级联清理（评论/站内信/媒体文件）在应用层执行，不依赖数据库外键级联（媒体文件在磁盘，必须应用层删）。
