# Spec: 新首页与农历天气批次（homepage-v2）

**Status:** ready-for-agent ｜ 来源：grilling 共识（2026-10-20）｜ 术语随 GLOSSARY.md

## Problem Statement

首页信息价值低（入口列表）且内容记录缺少时间与场景维度——用户希望记录时留下"何时（农历）+何地（天气/城市）"的生活切片，并让首页成为精美实用的"记录痕迹"总览。

## Solution

内容保存链路加入农历与天气快照；首页重构为"今日卡→统计→热力格→足迹→那年今天→互动→月度回顾→里程碑→我的时间线"九层结构；底部导航重组为六 tab。

## 实现决策（grilling 敲定）

- **天气/定位全客户端化**：浏览器直调 IP 定位（ipwho.is 类免费服务）+ Open-Meteo（免 key）；可选浏览器 Geolocation 授权提升精度；**禁止服务端代查**——出差到哪记的就是哪。失败/不准时手动改选天气图标兜底
- **保存即快照**：发布 API 接受天气快照（城市+现象+气温）；农历由后端 .NET 内置 `ChineseLunisolarCalendar` 计算（干支年+农历月日+节气，节气用简化表）落库
- **展示**：详情页全显（`乙巳年 腊月初一 · 大雪 ｜ 杭州 · 晴 · 12°C`），列表页只显天气；旧内容天气不回补，农历由 createdAt 推导显示
- **导航重组**：六 tab 首页/随记/日志/收到/主题/设置；主题页=现设置页（外观）；设置页=旧首页 hub 入口（好友/搜索/PAT/导入导出/管理后台/退出）；搜索上移为随记/日志页标题栏搜索图标；我的时间线并入首页底部
- **首页九模块**（自上而下）：今日卡 / 统计数字行（随记/日志/好友/连续记录天数） / 近90天热力格（点格跳当天） / 足迹（城市时间线，同城连续去重，源=天气快照城市） / 那年今天（无历史隐藏） / 互动摘要（近7天评论+被@数） / 月度回顾（本月篇数/城市/最常天气） / 里程碑（第100篇等徽章） / 我的时间线（带筛选）
- **设计纪律**：新页面设计先出 frontend-design 方案（token/排版/布局评审）再实现；随记/日志两页的整体设计另行讨论，本批次不动其结构
- t19 中断遗留的三处布局修正（双按钮/内容列居中/空态垂直居中）并入 03 号票收尾

## Out of Scope

随记/日志两页的整体重设计（另行讨论）；小程序/桌面端；天气历史 API（付费/需 key）；农历回填天气。
