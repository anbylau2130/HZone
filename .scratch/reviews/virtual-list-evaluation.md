# 虚拟列表（时间线 DOM 复用）实施评估 —— 2026-10-28

## 结论：当前不实施。

## 实测依据（headless Chromium 900×800，dev 库真实数据全量滚动加载）

| 指标 | 数值 |
|---|---|
| 全量加载卡片数 | 42（首页时间线滚到底） |
| 总 DOM 节点 | 3,072 |
| 单卡平均节点 | ~70（35 卡样本 2,063 节点推算） |
| 连续滚动 2s rAF 帧率 | 51 fps（60 满帧；headless 本身有折损，实机更高） |
| 首屏（一周窗口 35 卡） | 刷新即出，无可感知延迟 |

## 推理

- 虚拟列表收益区间通常在 **500~1000+ 列表项**（~3.5万+ DOM 节点，布局/合成开始掉帧）。
- 本产品单人内容量级：一年日均 1 条 ≈ 365 条；且首页首屏只拉一周窗口、
  更早内容按 (CreatedAt,Id) 键集游标 20 条/页惰性追加——DOM 只随用户
  主动滚动增长，不会一次性铺开。
- 卡片行含懒挂载的编辑器预览（AsyncCherryEditor），重度节点已做隔离。

## 触发条件（何时重评）

- 单列表卡片实际渲染数 > 500，或实机滚动帧率 < 45fps；
- 届时优先考虑 content-visibility: auto（CSS 级窗口化，改动远小于完整虚拟列表），
  再考虑组件级虚拟滚动。
