# Spec: HZone MVP

**Status:** ready-for-agent ｜ 来源：grilling 共识 + docs/PRD.md

## Problem Statement

小圈子用户（十几人）想要一个安静的分享空间：现有平台（QQ空间）广告泛滥、数据锁死在云端、外部 agent 无法访问；推送和 Feed 把"分享"变成了"表演"。用户需要一个自托管、零打扰、数据自主、agent 可读写的定向分享工具。

## Solution

HZone：自托管的私密定向分享社区。用户发布说说与日志，通过 @ 指定每条内容的可见名单（作者+被@者）；零推送、零 Feed；互动（@、评论）只产生登录时可见的站内信；提供 PAT REST API 供后续 MCP server 与 agent 读写。

## User Stories

**账号与注册**
1. 作为管理员，我想在实例首次启动时通过初始化向导创建账号并配置 SMTP，以便实例开箱可用。
2. 作为用户，我想用邀请码+邮箱+密码注册并通过邮件验证，以便受邀加入圈子。
3. 作为用户，我想生成一次性、带有效期、有配额的邀请码，以便邀请朋友而不失控。
4. 作为管理员，我想全局关闭邀请功能，以便控制圈子规模。
5. 作为用户，我想通过邮箱重置密码，以便找回账号。
6. 作为用户，我想用邮箱+密码登录，以便访问内容。

**好友关系**
7. 作为用户，我想向其他用户发起好友申请，对方同意后成为双向好友，以便进入彼此的 @ 候选范围。
8. 作为用户，我想查看/移除好友，以便管理熟人圈。

**内容与可见性**
9. 作为用户，我想发布说说（文本+≤9图/视频/音频）并选择 @ 对象（双向好友多选），以便定向分享生活。
10. 作为用户，我想发布日志（标题+Markdown 正文+图片）并选择 @ 对象，以便定向写长文。
11. 作为用户，我想不 @ 任何人发布内容（私密笔记），以便自用记录。
12. 作为被 @ 者，我想在"收到的内容"列表里看到所有 @ 我的内容，以便发现别人分享给我的东西。
13. 作为非可见名单成员，我想被明确拒绝访问内容（404 而非 403），以便内容存在性也不泄露。
14. 作为作者，我想随时修改可见名单：新增者收站内信、被移除者立即失权，以便控制扩散。
15. 作为作者，我想编辑正文/媒体、硬删除内容（级联清理评论、站内信、媒体文件），以便管理自己的数据。
16. 作为用户，我想访问好友主页并看到"Ta 发的、@ 了我的内容"，以便主动浏览。
17. 作为用户，我想按关键词搜索自己的日志与说说，以便找回历史内容。

**互动**
18. 作为可见名单成员，我想评论内容，评论对整个名单可见，以便小范围讨论。
19. 作为用户，我想在登录后从站内信看到被 @ 和收到评论的事件，以便不错过互动且不被打扰。

**数据与迁移**
20. 作为用户，我想整站导出 zip（日志 md+说说媒体+元数据清单），以便备份与迁移。
21. 作为用户，我想 zip 批量导入 md 日志（默认私密），以便内容搬进来。
22. 作为用户，我想对导入内容批量编辑 @ 名单，以便快速定向分享。
23. 作为用户，我想生成/吊销个人访问令牌（PAT），以便我的 agent 通过 REST API 读写我可见的内容。
24. 作为 agent，我想用 PAT 调 API 完成发内容/读可见内容/评论/搜索，以便自动化管理主人的数据。

**界面与个性化**
25. 作为用户，我想在中/英文界面间切换，以便用母语使用。
26. 作为用户，我想自定义主题配色（design token）并跨端同步，以便"自己装修"。

**管理员**
27. 作为管理员，我想配置媒体上限（默认图 10MB/视频 200MB·5min/音频 50MB）与全局开关，以便适配自己的设备。
28. 作为管理员，我想配置 SMTP，以便注册验证与密码重置邮件可用。

## Implementation Decisions

- **后端**：.NET 8 ASP.NET Core Web API；EF Core 抽象四库（SQLite 开发默认；SQLServer/PG/MySQL 部署可选，连接串切换）。
- **可见性单一入口**：可见名单校验收敛到数据层单一查询入口（ContentVisibility 查询），界面与 API 共用；非可见名单成员访问内容一律 404。
- **通知**：无推送、无 Feed。事件（被@、评论）只写站内信，登录后拉取。
- **账号**：邮箱即账号；密码 bcrypt；PAT 落库存哈希（生成时明文仅展示一次）。
- **媒体**：本地磁盘目录（路径可配），DB 存元数据；上限管理员可配；图片自动压缩+缩略图；视频压缩依赖 ffmpeg（无则按原上限拒绝）——本地测试环境用文件型 IEmailSender/压缩降级，不依赖外部服务。
- **正文存 DB** 为权威数据源；.md 是导出产物。
- **前端**：uni-app（Vue3），一套代码编译 H5 + Android/iOS；MVP 测试只针对 H5（本地浏览器）。
- **主题**：全部颜色/圆角/字号走 design token；用户主题跟随账号存储。
- **i18n**：中文+英文语言包，全文案走 i18n 框架。
- **测试 seam（两处，均为最高可测点）**：
  1. HTTP API 边界：`WebApplicationFactory` 进程内起真实 API + 内存/临时 SQLite，覆盖全部 e2e 场景（注册→加好友→发内容→可见性→评论→站内信→导出导入→PAT）。
  2. UI 边界：Playwright 驱动真浏览器访问本地运行的 H5（本地 `dotnet run` + 本地静态 H5，不用 Docker），覆盖登录、发布、@、可见性、评论、站内信、主题切换。
- 部署形态（Docker）不在 MVP 验收内。

## Testing Decisions

- 好的测试只测外部行为（HTTP 请求/响应、页面可见元素），不测实现细节。
- **e2e（API）**：每个用户故事至少一条进程内 HTTP 场景测试；可见性规则（13/14）是重点负路径测试。
- **UI e2e**：核心旅程（注册→登录→发说说@好友→好友收站内信→评论→搜索→切主题/语言）走 Playwright。
- 单元测试仅用于纯逻辑（如邀请码有效期/配额判定、压缩决策），不追求覆盖率指标。
- 无既有测试先例（绿地），首张测试票建立模式。

## Out of Scope（MVP 不做）

MCP server、移动端推送、邮件通知（站外）、小程序、桌面端、楼中楼评论、点赞、各库全文索引、Docker 部署验收、导入时按配置指定 @ 名单。
